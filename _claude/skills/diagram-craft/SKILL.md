# 図解の型と作法

show-me が「どの表現形式で見せるか」を選ぶ skill。これは**スイムレーン系の図を選んだあとの作法**。
show-me 本体は編集しない（`claude plugin update` で消える）。

## 1. 型の選択

**工程を説明する図で、単線のチェーン（箱→箱→箱）にしてはいけない。**
「誰が待っているか」「何往復するか」「誰の工数か」が全部消える。

担当レーン（横帯）× 時間軸（左→右）のスイムレーンにする。レーンは登場する担当者ぶんだけ引く。

```text
事業部  ██申請                    ██直す        ██直す
法務          ██形式チェック  ██法務判断
AI                          ┈┈Gem(手作業)┈┈
```

- 使われていないレーン（箱が1つしかない、線が空っぽ）は**それ自体が主張**になる。消さない。
- Before/After は**同じレーン構成・同じスケール**で並べる。差分（往復が消える / 箱が減る / レーンが増える）が形で読める。

## 2. コネクタはカギ線（直交）

**箱の右辺から出る → レーンに沿って横に走る → 相手の箱の中心 x で直角に曲がる → 上辺または下辺に垂直に刺さる。**

```
M<右辺x>,<出発レーンy> H<相手の中心x> V<相手の箱の辺y ±4>
```

- 矢尻が箱の辺に対して**直角に入る**。どこへ向かう線か一目で追える。
- やってはいけない: 右辺から出てすぐ縦に落ち、数 px の横棒で左辺に刺す。ほぼ縦線に見えて不自然。
- 手戻りループは Z 字（下 → 左 → 下）で戻し、行きの線とは**別の x** で相手の上辺に入れる。
- パスは `H` と `V` だけで書く。斜線・曲線が混ざったら直交になっていない。

## 3. 色と線種は意味に固定し、両方の図で使い回す

| 記号 | 意味 |
|---|---|
| 朱（seal） | これから解消する対象（無駄な工程、手戻りループ、手作業） |
| アクセント（藍など） | 新しく入るもの、その図の主役 |
| アンバー（wait） | 待ち時間 |
| 破線 | 手作業・システムに繋がっていない |
| 実線 | 自動・接続済み |

Before で朱だったものが After でアクセントに変わる、破線が実線になる、という**色の移動**で対比が成立する。
凡例は同じ記号が繰り返されるときだけ置く。1回しか出ない記号は線そのものにラベルを書く。

## 4. 数値の扱い

- **実測値と未計測を混ぜない。** 「AI の処理は数分（実測）」と「全体のリードタイム（未計測）」はキャプションで切り分ける。
- 箱の幅・図の長さは**順序**であって実時間ではない。そう読まれる形なら明記する。
- 効果を盛らない。ベースラインが無いなら「本番運用後に計測します」と書く方が資料として強い。

## 5. 文言

- 箱の中は**短く**。「日付・条番号・金額・必須条項を目視で確認」→「形式のミスを目で確認」。
- 説明文は箱に入れず `figcaption` へ。図の中の文字は 11〜13px、1〜3語。
- 見出しに結論を入れる。「いま」ではなく「いま — 法務の対応が2段階。AIへの依頼も手作業」。

## 6. Artifact でのインライン SVG 実装

- `<figure>` + `<svg role="img" aria-label="…">` + `<figcaption>`。
- **SVG の中に `<style>` を置かない。** ページ側の `<style>` で `.flow-svg .b-ai { fill: var(--accent-soft) }` のようにクラスで当てる。
  これでライト/ダークのトークンがそのまま効く。
- `marker` は fill をクラス指定にして**色ごとに複数定義**する（`#ah`, `#ah-w`, `#ah-s`）。1つを使い回すと色が揃わない。
- `viewBox` でサイズを決め、`.svg-scroll { overflow-x: auto }` + `min-width` で横スクロールさせる。
- 日本語は約 13px/文字（font-size 13）。箱の幅を超えるなら `<tspan>` で 2 行に割る。

## 7. 実装後の検証（毎回やる）

```python
# タグ balance（SVG の空要素を VOID に足す）/ トークン外の生 hex が無いか /
# コネクタが H・V だけか / rect が viewBox に収まっているか / class に対応する CSS があるか
```

目視より速く、ダークテーマ崩れとレイアウト破綻を確実に潰せる。

## 8. 進め方

**実装の前にテキストのスケッチを出して合意を取る。** SVG を書き切ってから方向性が違うと分かると全部やり直しになる。

```text
いま      事業部 ██起票                    ██直す
          法務        ┄待ち┄ ███目視確認  ███判断
```

この 3 行で「レーン構成」「往復の有無」「待ちの位置」が確認できる。
